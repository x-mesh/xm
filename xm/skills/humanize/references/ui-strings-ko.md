# UI 문자열 한글화 규칙 (ui 모드)

`humanize ui` 모드가 사용하는 규칙집. 대상은 앱·웹 화면과 CLI 출력에 그대로 표시되는 짧은 문자열이다. 영어 원문을 어순 그대로 옮겨 어색해진 문구를 한국어 UI 관례에 맞게 고친다.

산문용 규칙(`patterns-ko.md`)과 목적이 다르다. 저기는 "AI가 쓴 티"를 지우고, 여기는 "영어를 그대로 옮긴 티"를 지운다. AI가 쓰지 않은 문구에도 적용된다.

처음부터 한국어로 쓴 문구도 대상이다. 그런 문구는 직역체가 드물어 S 규칙에 걸리는 곳이 적다. 대신 같은 것을 여러 이름으로 부르거나, 내부에서만 통하는 말을 쓰거나, 실제 동작과 다른 것을 약속한다. 이런 문제는 `ui-meaning.md`의 용어 목록과 의미 검토가 잡는다. S 규칙에 걸린 곳이 적다는 이유로 문구가 괜찮다고 판단하지 않는다.

## 역할

번역이 아니라 편집이다. 뜻은 그대로 두고 표현만 고친다.

기능을 새로 해석하거나, 없는 동작을 지어내거나, 문구를 빌미로 UX 결정을 바꾸지 않는다. 원문이 설명하지 않은 조건·경고·부작용을 추가하지 않는다.

## 입출력 계약

### 입력

JSON 배열을 1급 입력으로 삼는다.

```json
[
  { "key": "settings.app.pasteShelf.label", "ko": "복사한 텍스트를 붙여넣기 선반에 저장", "en": "Save copied text to paste shelf", "type": "toggle_label" },
  { "key": "settings.app.pasteShelf.desc", "ko": "터미널에서 Cmd+C로 복사한 텍스트를 암호화하지 않고 7일 동안 디스크에 저장합니다.", "en": "...", "type": "desc" }
]
```

`en`과 `type`은 없을 수 있다. 없으면 `key`와 문맥으로 추론하고, 추론했다는 사실을 `note`에 적는다.

`context`도 선택 필드다. 그 컨트롤이 실제로 하는 일을 적으며, `ui-meaning.md`의 의미 검토가 이 값을 근거로 쓴다. 이 계약은 영문 대상(`ui-strings-en.md`)도 함께 쓰며, 그때는 `en`이 편집 대상이다.

`loc`(`경로:줄`)과 `group`(화면 영역 이름)도 선택 필드다. 입력이 소스 파일이나 화면일 때 쓴다. 소스에 `key`가 없으면 `key`를 지어내지 않고 `loc`과 `group`만 적는다.

입력이 소스 파일(`Localizable.strings`, `ko.json`, `messages.ts`, CLI 도움말·메시지 정의 등)이거나 화면·기능 이름이면 먼저 위 형태의 배열로 정규화한 뒤 처리한다. 문구가 템플릿과 서버 코드에 흩어져 있으면 `ui-meaning.md`의 `Input from a codebase` 절차로 뽑는다. 파일을 직접 수정하지 않는다. 사용자가 명시적으로 요청할 때만 `ui-meaning.md`의 `Applying to files` 절차로 반영한다.

### 출력

입력이 문자열 배열이면 JSON 배열만 낸다. 설명 문장이나 마크다운 코드펜스를 앞뒤에 붙이지 않는다.

입력이 소스 파일이나 화면이면 배열 대신 `ui-meaning.md`의 `Report for file or screen input` 형식으로 보고한다. 수백 항목짜리 배열은 사람이 읽을 수 없고, 아직 파일에 반영하지 않았다는 사실도 전하지 못한다. 보고의 각 항목은 아래 필드를 그대로 쓴다.

```json
[
  {
    "key": "settings.app.pasteShelf.label",
    "before": "복사한 텍스트를 붙여넣기 선반에 저장",
    "after": "클립보드 기록",
    "rules": ["S1-1", "G-3"],
    "note": "",
    "flag": false
  }
]
```

| 필드 | 의미 |
|------|------|
| `rules` | 적용한 규칙 코드. 이 문서의 S·O 코드와 `ui-meaning.md`의 M 코드를 그대로 쓴다. 용어집 적용은 `G-<번호>`, 용어 목록에서 정한 이름은 `G-P`. `after`가 `before`와 다르면 코드가 하나 이상 있어야 한다 |
| `note` | 추론 근거, 확인이 필요한 질문, 용어집 충돌 기록. 없으면 빈 문자열 |
| `flag` | 원문 뜻을 확신할 수 없으면 `true` |
| `loc` | 입력에 있으면 그대로 돌려준다 |

`flag`가 `true`면 `after`를 `before`와 같게 두고, `note`에 무엇을 모르는지 질문 형태로 적는다. 짐작해서 고치는 것보다 남겨 두는 쪽이 낫다.

고칠 필요가 없으면 `after`를 `before`와 같게 두고 `rules`를 빈 배열로 낸다. 억지로 손대지 않는다.

### 화면 단위 묶기

`key`의 마지막 마디를 뺀 접두사가 같은 항목을 한 화면으로 본다. 예를 들어 `settings.app.pasteShelf.label`과 `settings.app.pasteShelf.desc`는 같은 묶음이다. S1-2(레이블·설명 중복)와 S1-4(종결 혼재)는 이 묶음 안에서 판정한다.

`key`가 없고 `group`이 있으면 `group`이 같은 항목을 한 화면으로 본다. 둘 다 없으면 입력 배열의 순서를 화면 순서로 간주하고, 그 사실을 `note`에 적는다.

용어 통일은 묶음 안이 아니라 입력 전체에서 판정한다. 절차는 `ui-meaning.md`의 `Term inventory`에 있다.

## 5원칙

**1. 레이블은 이름, 설명은 문장.** 토글 레이블은 그 기능을 켠 상태를 가리키는 짧은 명사구다. 켰을 때 무슨 일이 벌어지는지는 설명문이 맡는다. 레이블에 조사 "를/을 … 에/에서"가 함께 들어가면 문장이 됐다는 신호다.

**2. 설명은 한 문장.** 경고나 전제 조건은 문장을 끊어 두 번째 문장으로 뺀다. 세 문장이 되면 뺄 말이 있는지 먼저 본다. 다만 문장 수를 맞추려고 관계없는 사실을 `-고`, `-며`로 잇거나 원문에 없는 서술어를 넣지 않는다. 사실이 셋이면 세 문장으로 둔다.

**3. 구현 용어를 밖으로 내보내지 않는다.** 코디네이터, 피어, 미러, 소켓, 데몬, 페인 같은 말은 설계 문서의 단어다. 사용자에게는 그 말이 가리키는 실제 대상을 쓴다. 설정 이름에 이미 굳어진 용어는 레이블에 남기되, 설명문에서 한 번 풀어 준다.

**4. 한 화면 안에서 종결을 통일한다.** 설명문은 "~합니다"로 끝낸다. "~하세요" 명령형은 사용자가 지금 행동해야 하는 오류·확인 다이얼로그에서만 쓴다.

**5. 이름으로 충분한 자리에 동사를 쓰지 않는다.** 버튼, 메뉴, CLI 도움말, 진행·완료 상태 줄은 무엇을 하는지 이름만 보여 주면 된다. 이 자리의 `저장하기`, `저장합니다`, `저장하고 있습니다`는 영어 동사를 옮긴 군더더기다. `저장`, `저장 중…`, `저장 완료`처럼 동작 명사로 쓴다. 완결된 문장은 설명문, 오류, 대화 상자처럼 문장이 필요한 자리에만 쓴다.

## type별 규칙

| type | 형태 | 길이 | 마침표 |
|------|------|------|--------|
| `section_header` | 명사구 | 10자 이내 | 없음 |
| `toggle_label` | 명사구. 동사로 끝내지 않는다 | 공백 포함 20자 이내 | 없음 |
| `select_label` | 명사구 | 20자 이내 | 없음 |
| `select_option` | 명사구. 레이블 단어를 반복하지 않는다 | 12자 이내 | 없음 |
| `desc` | 완결된 문장 | 한 문장 45자 내외, 최대 2문장 | 있음 |
| `button` | 동작 명사 (`저장`, `삭제`, `다시 시도`). `~하기`·`~합니다`로 끝내지 않는다 | 5자 이내 | 없음 |
| `menu_item` | 명사구 (`새 창`, `다른 이름으로 저장…`) | 20자 이내 | 없음 |
| `dialog_body` | 완결된 문장. 명령형 허용 | 2문장 이내 | 있음 |
| `empty_state` | 상황 한 문장 + 다음 행동 한 문장 | 2문장 | 있음 |
| `error` | 무엇이 실패했는지 + 무엇을 하면 되는지. CLI 오류도 같다 | 2문장 | 있음 |
| `cli_help` | 명령·플래그 설명. 명사구 (`현재 상태 표시`, `설정 파일 경로`) | 한 줄, 40자 이내 | 없음 |
| `cli_progress` | `<대상> <동작> 중…`. 한자어 동작 명사는 `하는`을 빼고(`원격 서버와 동기화 중…`), 명사형이 없는 고유어 동사만 `~는 중…`(`설정 파일 불러오는 중…`) | 한 줄 | 없음 |
| `cli_done` | `<동작> 완료` 또는 `<동작> 완료: {값}` (`저장 완료: {path}`) | 한 줄 | 없음 |
| `table_header` | 그 열에 담기는 값의 이름. 명사구 | — | 없음 |
| `tab` | 그 탭에 모인 것의 이름. 명사구 | — | 없음 |
| `badge` | 상태 이름. 같은 자리에 나오는 상태끼리 형태를 맞춘다 (`대기`, `완료`, `보류`) | — | 없음 |
| `tooltip` | 완결된 문장. 화면에 이미 보이는 말을 되풀이하지 않는다 | 2문장 이내 | 같은 화면의 `tooltip`끼리만 맞춘다. 모두 같으면 고치지 않고, 섞였으면 많은 쪽을 따른다 |
| `legend` | 표시가 뜻하는 값. 명사구. 같은 범례 안에서 표기를 맞춘다 | — | 없음 |
| `placeholder` | 입력할 내용의 이름이나 예시. 명사구 | — | 없음 |
| `notification` | 화면 밖에서 읽힌다. 무슨 일이 몇 건 일어났는지 먼저 쓰고, 화면과 같은 용어를 쓴다 | — | 문장이면 있음 |

길이와 문장 수 상한은 목표치다. 넘겼다고 뜻을 깎거나 문장을 억지로 잇지 말고, 넘긴 사실을 `note`에 적는다.

드롭다운 설명문은 특정 옵션의 동작이 아니라 그 설정이 무엇을 정하는지를 쓴다. "새 워크스페이스를 현재 워크스페이스 바로 뒤에 넣습니다"는 `현재 다음` 옵션만의 설명이라, 다른 값을 고르면 거짓말이 된다.

## S1 — 무조건 수정

한 번이라도 나오면 고친다.

| 코드 | 패턴 | 예 | 처방 |
|------|------|-----|------|
| S1-1 | 토글 레이블이 문장 | 복사한 텍스트를 붙여넣기 선반에 저장 | 명사구로: 클립보드 기록 |
| S1-2 | 레이블과 설명문 중복 | 레이블 "세션 복원" + 옵션 "이전 세션 복원" | 옵션은 `복원` / `새로 시작` |
| S1-3 | 구현 용어 노출 | 피어 워크스페이스를 미러 동작으로 | 다른 컴퓨터의 워크스페이스를 읽기 전용으로 |
| S1-4 | 종결 혼재 | "…올립니다. …끄세요." | 한쪽으로 통일 |
| S1-5 | 활성화·비활성화 | 알림 기능을 활성화합니다 | 켜다 / 끄다 |
| S1-6 | 영어 구문 직역 | ~하는 것을 허용합니다 / ~할 수 있도록 합니다 | 동작을 직접 서술 |
| S1-7 | 마침표 규칙 불일치 | 설명문 일부만 마침표 | type별 규칙표대로 |
| S1-8 | 이중 피동 | 표시되어집니다 / 저장되어진 | 능동으로 |
| S1-9 | 드롭다운 설명이 한 옵션만 서술 | 위 드롭다운 항목 참조 | 설정 전체를 서술 |
| S1-10 | 명사구 자리의 동사 종결 | 버튼 `저장하기`, 도움말 `현재 상태를 보여 줍니다.`, 진행 `파일을 저장하고 있습니다...` | 동작 명사로: `저장`, `현재 상태 표시`, `파일 저장 중…` |

### 적용 범위

형태 규칙을 적용하다가 뜻이 상하는 곳이 세 군데 있다.

- **S1-2**: 겹치는 말을 뺄 때, 그 레이블을 같은 목록의 다른 레이블과 구별해 주는 대상어는 남긴다. 설명문이 그 말을 한다는 이유로 레이블에서 빼지 않는다. 레이블 `초대 링크 만료`를 설명문 `만든 지 이 시간이 지나면 링크를 쓸 수 없습니다.` 때문에 `만료`로 줄이면, 목록에서 무엇이 만료되는지 알 수 없다.
- **S1-3**: 프로젝트 안에서만 통하는 이름도 구현 용어로 본다. 사건 별칭, 내부 코드명, 팀만 아는 수치 인용이 그렇다(`3차 장애 때처럼 큐가 밀리면 알립니다.`). 대신할 말을 모르면 `flag`를 `true`로 두고 무엇으로 바꿀지 묻는다.
- **S1-10**: `하다`가 붙는 동사에 적용한다(`저장하기` → `저장`, `초기화하기` → `초기화`). 고유어 동사의 `~기`(`담기`, `지우기`, `줄이기`)는 그 자체가 동작 이름이므로 그대로 둔다. 형태를 맞추려고 고유어를 한자어로 바꾸지 않는다. 버튼의 낱말을 바꿨으면 그 버튼이 여는 확인 창도 같은 낱말을 쓰는지 본다.

## S2 — 반복되면 수정

문구 묶음 안에서 되풀이될 때 고친다. 한 번뿐이면 남겨도 된다.

| 코드 | 패턴 | 처방 |
|------|------|------|
| S2-1 | "~를 통해", "~에 대한", "~에 있어서", "~의 경우" | 조사와 동사를 직접 고른다 |
| S2-2 | 명사 4개 이상 연쇄 (워크스페이스 알림 순서 변경 설정) | 조사를 넣어 끊는다 |
| S2-3 | "~들" 복수 접미사 | 삭제 |
| S2-4 | 소유격 "당신의", "사용자의" | 삭제. 한국어 UI는 주어를 생략한다 |
| S2-5 | 괄호 영어 병기 | 이미 통용되는 한국어만 남긴다 |
| S2-6 | "표시합니다"로 모든 설명 종결 | 실제 동사로 (보여줍니다, 올립니다, 묻습니다, 보관합니다) |
| S2-7 | "~기 위해서는" | "~하려면" |
| S2-8 | 접속 부사로 문두 시작 (또한, 따라서, 즉) | 삭제 |

## O — 맞춤법

뜻을 바꾸지 않는 교정이다.

| 코드 | 패턴 | 예 | 처방 |
|------|------|-----|------|
| O-1 | 조사 띄어쓰기, 맞춤법, 문장 부호 | `Wi-Fi 에 연결합니다.` | `Wi-Fi에 연결합니다.` |

- 같은 어긋남이 입력 곳곳에서 되풀이되면 항목마다 따로 내지 않고 한 묶음으로 건수와 함께 낸다. 프로젝트가 일부러 그렇게 쓰는지 알 수 없으면 고치지 말고 한 번 묻는다.
- O-1은 결과의 맨 뒤에 둔다. 고친 항목이 대부분 O-1이라면 의미 검토와 용어 목록을 건너뛴 것이다.

## 손대지 말 것

- 제품명과 고유명사 (`term-mesh`, `Command Palette`)
- 단축키 표기 (`Cmd+Q`, `Ctrl+Shift+P`)
- 환경 변수, 파일 경로, CLI 플래그, 코드 식별자 (`TERMMESH_COORDINATOR_ENABLED=1`)
- 숫자, 기간, 단위 (`7일`을 `일주일`로 바꾸지 않는다)
- 자리표시자 (`{count}`, `{name}`, `%@`, `%1$s`)

자리표시자 뒤에 조사가 붙으면 `{name}을(를)` 같은 병기를 만들지 말고, 조사가 필요 없게 문장을 다시 짠다.

- 전: `{name}을(를) 삭제할까요?`
- 후: `삭제: {name}` 또는 `이 워크스페이스를 삭제할까요?`

## 용어집

같은 개념을 화면마다 다르게 부르면 사용자는 다른 기능으로 읽는다. 왼쪽 원어를 오른쪽 한 가지 표현으로 통일한다.

아래 표는 출발점일 뿐이다. 프로젝트의 용어는 대부분 여기에 없으므로, 입력 전체에서 용어 목록을 만들어 같은 것을 가리키는 이름을 하나로 정한다(`ui-meaning.md`의 `Term inventory`). 그렇게 정한 이름을 적용했으면 `rules`에 `G-P`로 적는다.

### 프로젝트 용어집

`.xm/ui-glossary.json`이 있으면 먼저 읽고, 그 항목이 아래 기본 용어집보다 우선한다.

```json
{
  "peer host": { "ko": "다른 컴퓨터", "note": "미확정", "scope": "desc" },
  "coordinator": { "ko": "코디네이터", "note": "설명문에서 '항상 켜 두는 서버'로 한 번 풀어 준다" },
  "pane": { "ko": "패널" }
}
```

| 필드 | 의미 |
|------|------|
| `ko` | 사용자에게 보이는 말 |
| `note` | 아직 확정 전이거나 사용 조건이 있을 때 |
| `scope` | 적용 범위. `label` / `desc` / 생략(전체) |

`note`에 `미확정`이 붙은 항목은, 다른 문구에서 이미 굳은 번역어가 보이면 그쪽을 따르고 그 사실을 출력의 `note`에 적는다.

파일이 없으면 기본 용어집만 적용하고, 프로젝트 고유 용어(구현 이름에서 온 말)는 S1-3으로 처리하되 대체어를 확신할 수 없으면 `flag`를 `true`로 둔다.

## 기존 산문 패턴과의 관계

아래 S 규칙은 `patterns-ko.md`의 패턴과 같은 현상을 UI 문맥에서 다시 정의한 것이다. 출력의 `rules`에는 S 코드를 쓴다.

| S 코드 | 대응 산문 패턴 |
|--------|---------------|
| S1-6 | KO-2 영어 직역체, KO-20 "가지고 있다" 직역체 |
| S1-8 | KO-21 이중 피동 |
| S2-1 | KO-2 감시 표현 |
| S2-2 | KO-4 명사화 남발 |
| S2-5 | KO-14 불필요한 영어 병기 |
| S2-8 | KO-7 접속사 남용 |

`patterns-ko.md`의 나머지 패턴은 산문 길이를 전제로 하므로 UI 문자열에 적용하지 않는다. 특히 KO-5(균일한 문장 길이), KO-31(단문 일변도), KO-32(동일 종결어미 반복)는 UI에서 **오히려 지켜야 할 성질**이다. 설정 화면의 설명문은 길이도 종결도 같아야 읽힌다.

## 기준 예시

| before | after |
|--------|-------|
| 복사한 텍스트를 붙여넣기 선반에 저장 | 클립보드 기록 |
| 터미널에서 Cmd+C로 복사한 텍스트를 암호화하지 않고 7일 동안 디스크에 저장합니다. | 터미널에서 복사한 텍스트를 7일간 보관합니다. 암호화하지 않고 디스크에 저장하니 비밀번호를 복사할 때는 끄는 편이 안전합니다. |
| 알림 시 순서 변경 | 알림 오면 맨 위로 |
| 알림을 받은 워크스페이스를 맨 위로 올립니다. 단축키 위치를 고정하려면 끄세요. | 알림을 받은 워크스페이스를 목록 맨 위로 올립니다. 끄면 단축키 번호가 그대로 유지됩니다. |
| 종료 전 경고 | 종료할 때 확인 |
| Cmd+Q로 종료하기 전에 확인 창을 보여줍니다. | Cmd+Q를 누르면 정말 끌지 묻습니다. |
| 이름 변경 시 기존 이름 선택 | 이름 바꿀 때 전체 선택 |
| 로컬 워크스페이스와 피어 호스트를 분리하고, 피어 워크스페이스를 미러 동작으로 보여줍니다. | 내 컴퓨터의 워크스페이스와 다른 컴퓨터의 워크스페이스를 나눠서 보여줍니다. |
| 저장하기 (`button`) | 저장 |
| 현재 상태를 보여 줍니다. (`cli_help`) | 현재 상태 표시 |
| 설정 파일을 불러오고 있습니다... (`cli_progress`) | 설정 파일 불러오는 중… |
| 저장이 완료되었습니다. (`cli_done`) | 저장 완료 |

두 번째 예시는 원문에 없던 권고("끄는 편이 안전합니다")를 더한 것처럼 보이지만, 암호화하지 않는다는 사실이 원문에 있으므로 그 사실의 귀결을 밝힌 것이다. 원문에 근거가 없는 권고는 넣지 않는다.

## 자체 검증

출력을 내기 전에 항목마다 확인한다.

- [ ] `ui-meaning.md`의 의미 검토를 문체 규칙보다 먼저 마쳤고, 그 자체 검증을 통과했는가
- [ ] `after`가 원문에 없던 동작이나 조건을 만들어 내지 않았는가
- [ ] 숫자, 단축키, 환경 변수, 자리표시자가 글자 하나까지 같은가
- [ ] `toggle_label`이 동사나 "~기"로 끝나지 않는가
- [ ] `button`, `menu_item`, `cli_help`, `cli_progress`, `cli_done`이 `~하기`, `~합니다`, `~하고 있습니다`로 끝나지 않는가. 용어집 단어(`가져오기`, `내보내기`)와 굳은 명사(`붙여넣기`, `잘라내기`)는 예외다
- [ ] 설명문이 두 문장을 넘으면 `note`에 적었는가. 문장 수를 맞추려고 관계없는 사실을 잇거나 없던 서술어를 넣지 않았는가
- [ ] 같은 묶음의 설명문 종결이 섞이지 않았는가
- [ ] 용어집에 있는 말을 다른 번역어로 쓰지 않았는가. 입력 전체에서 같은 것을 두 이름으로 부르는 곳이 남지 않았는가
- [ ] 레이블에서 대상어가 빠지지 않았는가
- [ ] 버튼과 그 버튼이 여는 확인 창이 같은 낱말을 쓰는가
- [ ] `after`가 `before`와 다른 항목마다 규칙 코드가 있는가
- [ ] 뜻을 확신 못 하면서 `flag`를 `false`로 두지 않았는가
- [ ] 배열 입력이면 출력이 JSON 배열 하나이고 앞뒤에 설명이나 코드펜스가 없는가. 파일·화면 입력이면 보고 형식을 따랐고 첫 줄에서 파일을 고치지 않았다고 밝혔는가
