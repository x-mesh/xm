# UI 문자열 한글화 규칙 (ui 모드)

`humanize ui` 모드가 사용하는 규칙집. 대상은 앱·웹 화면에 그대로 표시되는 짧은 문자열이다. 영어 원문을 어순 그대로 옮겨 어색해진 문구를 한국어 UI 관례에 맞게 고친다.

산문용 규칙(`patterns-ko.md`)과 목적이 다르다. 저기는 "AI가 쓴 티"를 지우고, 여기는 "영어를 그대로 옮긴 티"를 지운다. AI가 쓰지 않은 문구에도 적용된다.

## 역할

번역이 아니라 편집이다. 뜻은 그대로 두고 표현만 고친다.

기능을 새로 해석하거나, 없는 동작을 지어내거나, 문구를 빌미로 UX 결정을 바꾸지 않는다. 원문이 설명하지 않은 조건·경고·부작용을 추가하지 않는다.

## 입출력 계약

### 입력

JSON 배열을 1급 입력으로 삼는다.

```json
[
  { "key": "settings.app.pasteShelf.label", "ko": "복사한 텍스트를 붙여넣기 선반에 저장", "en": "Save copied text to paste shelf", "type": "toggle_label" },
  { "key": "settings.app.pasteShelf.desc", "ko": "터미널에서 Cmd+C로 복사한 텍스트를 암호화하지 않고 7일 동안 디스크에 저장합니다.", "en": "...", "type": "desc" }
]
```

`en`과 `type`은 없을 수 있다. 없으면 `key`와 문맥으로 추론하고, 추론했다는 사실을 `note`에 적는다.

입력이 소스 파일(`Localizable.strings`, `ko.json`, `messages.ts` 등)이면 먼저 위 형태의 배열로 정규화한 뒤 처리한다. 파일을 직접 수정하지 않는다. 사용자가 명시적으로 요청할 때만 파일에 반영한다.

### 출력

JSON 배열만 낸다. 설명 문장이나 마크다운 코드펜스를 앞뒤에 붙이지 않는다.

```json
[
  {
    "key": "settings.app.pasteShelf.label",
    "before": "복사한 텍스트를 붙여넣기 선반에 저장",
    "after": "클립보드 기록",
    "rules": ["S1-1", "G-3"],
    "note": "",
    "flag": false
  }
]
```

| 필드 | 의미 |
|------|------|
| `rules` | 적용한 규칙 코드. 이 문서의 코드를 그대로 쓴다. 용어집 적용은 `G-<번호>` |
| `note` | 추론 근거, 확인이 필요한 질문, 용어집 충돌 기록. 없으면 빈 문자열 |
| `flag` | 원문 뜻을 확신할 수 없으면 `true` |

`flag`가 `true`면 `after`를 `before`와 같게 두고, `note`에 무엇을 모르는지 질문 형태로 적는다. 짐작해서 고치는 것보다 남겨 두는 쪽이 낫다.

고칠 필요가 없으면 `after`를 `before`와 같게 두고 `rules`를 빈 배열로 낸다. 억지로 손대지 않는다.

### 화면 단위 묶기

`key`의 마지막 마디를 뺀 접두사가 같은 항목을 한 화면으로 본다. 예를 들어 `settings.app.pasteShelf.label`과 `settings.app.pasteShelf.desc`는 같은 묶음이다. S1-2(레이블·설명 중복)와 S1-4(종결 혼재)는 이 묶음 안에서 판정한다.

`key`가 없으면 입력 배열의 순서를 화면 순서로 간주하고, 그 사실을 `note`에 적는다.

## 4원칙

**1. 레이블은 이름, 설명은 문장.** 토글 레이블은 그 기능을 켠 상태를 가리키는 짧은 명사구다. 켰을 때 무슨 일이 벌어지는지는 설명문이 맡는다. 레이블에 조사 "를/을 … 에/에서"가 함께 들어가면 문장이 됐다는 신호다.

**2. 설명은 한 문장.** 경고나 전제 조건은 문장을 끊어 두 번째 문장으로 뺀다. 세 문장은 안 된다.

**3. 구현 용어를 밖으로 내보내지 않는다.** 코디네이터, 피어, 미러, 소켓, 데몬, 페인 같은 말은 설계 문서의 단어다. 사용자에게는 그 말이 가리키는 실제 대상을 쓴다. 설정 이름에 이미 굳어진 용어는 레이블에 남기되, 설명문에서 한 번 풀어 준다.

**4. 한 화면 안에서 종결을 통일한다.** 설명문은 "~합니다"로 끝낸다. "~하세요" 명령형은 사용자가 지금 행동해야 하는 오류·확인 다이얼로그에서만 쓴다.

## type별 규칙

| type | 형태 | 길이 | 마침표 |
|------|------|------|--------|
| `section_header` | 명사구 | 10자 이내 | 없음 |
| `toggle_label` | 명사구. 동사로 끝내지 않는다 | 공백 포함 20자 이내 | 없음 |
| `select_label` | 명사구 | 20자 이내 | 없음 |
| `select_option` | 명사구. 레이블 단어를 반복하지 않는다 | 12자 이내 | 없음 |
| `desc` | 완결된 문장 | 한 문장 45자 내외, 최대 2문장 | 있음 |
| `button` | 동사 | 5자 이내 | 없음 |
| `dialog_body` | 완결된 문장. 명령형 허용 | 2문장 이내 | 있음 |
| `empty_state` | 상황 한 문장 + 다음 행동 한 문장 | 2문장 | 있음 |
| `error` | 무엇이 실패했는지 + 무엇을 하면 되는지 | 2문장 | 있음 |

길이 상한은 목표치다. 넘겼다고 뜻을 깎지 말고, 넘긴 사실을 `note`에 적는다.

드롭다운 설명문은 특정 옵션의 동작이 아니라 그 설정이 무엇을 정하는지를 쓴다. "새 워크스페이스를 현재 워크스페이스 바로 뒤에 넣습니다"는 `현재 다음` 옵션만의 설명이라, 다른 값을 고르면 거짓말이 된다.

## S1 — 무조건 수정

한 번이라도 나오면 고친다.

| 코드 | 패턴 | 예 | 처방 |
|------|------|-----|------|
| S1-1 | 토글 레이블이 문장 | 복사한 텍스트를 붙여넣기 선반에 저장 | 명사구로: 클립보드 기록 |
| S1-2 | 레이블과 설명문 중복 | 레이블 "세션 복원" + 옵션 "이전 세션 복원" | 옵션은 `복원` / `새로 시작` |
| S1-3 | 구현 용어 노출 | 피어 워크스페이스를 미러 동작으로 | 다른 컴퓨터의 워크스페이스를 읽기 전용으로 |
| S1-4 | 종결 혼재 | "…올립니다. …끄세요." | 한쪽으로 통일 |
| S1-5 | 활성화·비활성화 | 알림 기능을 활성화합니다 | 켜다 / 끄다 |
| S1-6 | 영어 구문 직역 | ~하는 것을 허용합니다 / ~할 수 있도록 합니다 | 동작을 직접 서술 |
| S1-7 | 마침표 규칙 불일치 | 설명문 일부만 마침표 | type별 규칙표대로 |
| S1-8 | 이중 피동 | 표시되어집니다 / 저장되어진 | 능동으로 |
| S1-9 | 드롭다운 설명이 한 옵션만 서술 | 위 드롭다운 항목 참조 | 설정 전체를 서술 |

## S2 — 반복되면 수정

문구 묶음 안에서 되풀이될 때 고친다. 한 번뿐이면 남겨도 된다.

| 코드 | 패턴 | 처방 |
|------|------|------|
| S2-1 | "~를 통해", "~에 대한", "~에 있어서", "~의 경우" | 조사와 동사를 직접 고른다 |
| S2-2 | 명사 4개 이상 연쇄 (워크스페이스 알림 순서 변경 설정) | 조사를 넣어 끊는다 |
| S2-3 | "~들" 복수 접미사 | 삭제 |
| S2-4 | 소유격 "당신의", "사용자의" | 삭제. 한국어 UI는 주어를 생략한다 |
| S2-5 | 괄호 영어 병기 | 이미 통용되는 한국어만 남긴다 |
| S2-6 | "표시합니다"로 모든 설명 종결 | 실제 동사로 (보여줍니다, 올립니다, 묻습니다, 보관합니다) |
| S2-7 | "~기 위해서는" | "~하려면" |
| S2-8 | 접속 부사로 문두 시작 (또한, 따라서, 즉) | 삭제 |

## 손대지 말 것

- 제품명과 고유명사 (`term-mesh`, `Command Palette`)
- 단축키 표기 (`Cmd+Q`, `Ctrl+Shift+P`)
- 환경 변수, 파일 경로, CLI 플래그, 코드 식별자 (`TERMMESH_COORDINATOR_ENABLED=1`)
- 숫자, 기간, 단위 (`7일`을 `일주일`로 바꾸지 않는다)
- 자리표시자 (`{count}`, `{name}`, `%@`, `%1$s`)

자리표시자 뒤에 조사가 붙으면 `{name}을(를)` 같은 병기를 만들지 말고, 조사가 필요 없게 문장을 다시 짠다.

- 전: `{name}을(를) 삭제할까요?`
- 후: `삭제: {name}` 또는 `이 워크스페이스를 삭제할까요?`

## 용어집

같은 개념을 화면마다 다르게 부르면 사용자는 다른 기능으로 읽는다. 왼쪽 원어를 오른쪽 한 가지 표현으로 통일한다.

### 프로젝트 용어집

`.xm/ui-glossary.json`이 있으면 먼저 읽고, 그 항목이 아래 기본 용어집보다 우선한다.

```json
{
  "peer host": { "ko": "다른 컴퓨터", "note": "미확정", "scope": "desc" },
  "coordinator": { "ko": "코디네이터", "note": "설명문에서 '항상 켜 두는 서버'로 한 번 풀어 준다" },
  "pane": { "ko": "패널" }
}
```

| 필드 | 의미 |
|------|------|
| `ko` | 사용자에게 보이는 말 |
| `note` | 아직 확정 전이거나 사용 조건이 있을 때 |
| `scope` | 적용 범위. `label` / `desc` / 생략(전체) |

`note`에 `미확정`이 붙은 항목은, 다른 문구에서 이미 굳은 번역어가 보이면 그쪽을 따르고 그 사실을 출력의 `note`에 적는다.

파일이 없으면 기본 용어집만 적용하고, 프로젝트 고유 용어(구현 이름에서 온 말)는 S1-3으로 처리하되 대체어를 확신할 수 없으면 `flag`를 `true`로 둔다.

## 기존 산문 패턴과의 관계

아래 S 규칙은 `patterns-ko.md`의 패턴과 같은 현상을 UI 문맥에서 다시 정의한 것이다. 출력의 `rules`에는 S 코드를 쓴다.

| S 코드 | 대응 산문 패턴 |
|--------|---------------|
| S1-6 | KO-2 영어 직역체, KO-20 "가지고 있다" 직역체 |
| S1-8 | KO-21 이중 피동 |
| S2-1 | KO-2 감시 표현 |
| S2-2 | KO-4 명사화 남발 |
| S2-5 | KO-14 불필요한 영어 병기 |
| S2-8 | KO-7 접속사 남용 |

`patterns-ko.md`의 나머지 패턴은 산문 길이를 전제로 하므로 UI 문자열에 적용하지 않는다. 특히 KO-5(균일한 문장 길이), KO-31(단문 일변도), KO-32(동일 종결어미 반복)는 UI에서 **오히려 지켜야 할 성질**이다. 설정 화면의 설명문은 길이도 종결도 같아야 읽힌다.

## 기준 예시

| before | after |
|--------|-------|
| 복사한 텍스트를 붙여넣기 선반에 저장 | 클립보드 기록 |
| 터미널에서 Cmd+C로 복사한 텍스트를 암호화하지 않고 7일 동안 디스크에 저장합니다. | 터미널에서 복사한 텍스트를 7일간 보관합니다. 암호화하지 않고 디스크에 저장하니 비밀번호를 복사할 때는 끄는 편이 안전합니다. |
| 알림 시 순서 변경 | 알림 오면 맨 위로 |
| 알림을 받은 워크스페이스를 맨 위로 올립니다. 단축키 위치를 고정하려면 끄세요. | 알림을 받은 워크스페이스를 목록 맨 위로 올립니다. 끄면 단축키 번호가 그대로 유지됩니다. |
| 종료 전 경고 | 종료할 때 확인 |
| Cmd+Q로 종료하기 전에 확인 창을 보여줍니다. | Cmd+Q를 누르면 정말 끌지 묻습니다. |
| 이름 변경 시 기존 이름 선택 | 이름 바꿀 때 전체 선택 |
| 로컬 워크스페이스와 피어 호스트를 분리하고, 피어 워크스페이스를 미러 동작으로 보여줍니다. | 내 컴퓨터의 워크스페이스와 다른 컴퓨터의 워크스페이스를 나눠서 보여줍니다. |

두 번째 예시는 원문에 없던 권고("끄는 편이 안전합니다")를 더한 것처럼 보이지만, 암호화하지 않는다는 사실이 원문에 있으므로 그 사실의 귀결을 밝힌 것이다. 원문에 근거가 없는 권고는 넣지 않는다.

## 자체 검증

출력을 내기 전에 항목마다 확인한다.

- [ ] `after`가 원문에 없던 동작이나 조건을 만들어 내지 않았는가
- [ ] 숫자, 단축키, 환경 변수, 자리표시자가 글자 하나까지 같은가
- [ ] `toggle_label`이 동사나 "~기"로 끝나지 않는가
- [ ] 설명문이 두 문장을 넘지 않는가
- [ ] 같은 묶음의 설명문 종결이 섞이지 않았는가
- [ ] 용어집에 있는 말을 다른 번역어로 쓰지 않았는가
- [ ] 뜻을 확신 못 하면서 `flag`를 `false`로 두지 않았는가
- [ ] 출력이 JSON 배열 하나이고, 앞뒤에 설명이나 코드펜스가 없는가
